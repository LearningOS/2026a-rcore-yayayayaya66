# 实验三：进程管理

## 实验内容

实现 `spawn`，按程序名加载应用并创建子进程、建立父子关系、加入就绪队列；实现进程优先级设置和 stride 调度，适配时间获取及匿名映射接口。

## 问答：stride 调度

### 1. 8 位无符号数溢出

不一定轮到 p1。`p2.stride = 250` 增加 10 后，在 8 位无符号数下回绕为 4；若直接比较无符号值，4 小于 255，调度器会错误地继续选择 p2。这里区分数学上的累计值 260 和存储后的值 4。

### 2. 差值上界

理想模型中，每次只选择当前最小的 stride 增加自身步长；优先级至少为 2，因而单次增加的 `pass = BigStride / priority` 最多约为 `BigStride / 2`。从各进程 stride 相等、进程集合固定且持续可运行等前提出发，最大值与最小值之差可保持在该量级以内。新进程加入、阻塞和唤醒等情况需要额外维护这一前提，不能仅凭优先级下界推导任意状态的界。

### 3. 回绕比较器

当两个累计值的真实差距严格小于半个模数时，可将无符号回绕差值解释为有符号数，并反转比较结果以适配 Rust 的最大堆：

```rust
use core::cmp::Ordering;

fn heap_order(a: u64, b: u64) -> Ordering {
    let diff = a.wrapping_sub(b) as i64;
    if diff < 0 { Ordering::Greater }
    else if diff > 0 { Ordering::Less }
    else { Ordering::Equal }
}
```

示例是问答中的比较器设计，不是当前内核所使用的实现；距离恰好为半个模数时不能仅凭回绕值无歧义地确定先后。本仓库实际代码使用 `u128` 累计量和普通数值比较，扩大了溢出前的范围，但没有实现上述回绕比较。
